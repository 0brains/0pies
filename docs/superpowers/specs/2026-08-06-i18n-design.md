# 0pi.es internationalization — design

**Date:** 2026-08-06 · **Status:** approved pending review

## Goal

Make the whole site usable in 14 major world languages while keeping the
architecture that defines it: static generated HTML, data inlined, zero
tracking, works on `file://` and offline. The landing page's Ancient Egyptian
and Klingon easter eggs stay.

**Languages:** `es pt fr de it pl tr ru ar hi zh ja ko vi` + `en` (source) +
`egy kli` (landing-page fun, body-font swap only, unchanged behavior).

## Non-negotiable constraints

1. **Answer strings stay English.** The certifications are examined in
   English; answers, options, and zone names are the scoring keys of the
   sorting games. Translating them breaks scoring and study value. A localized
   UI string explains this once: "exam terms stay in English."
2. **Default page weight unchanged.** English pages ship byte-identical in
   size class to today. Translations must not be inlined into lab pages
   except the UI string dictionaries (~80–120KB total across all locales).
3. **`file://` never breaks.** Where lazy fetch fails (file://, offline),
   card content silently stays English while UI chrome still translates.
4. **Fail loudly at build time.** Missing locale keys or overlay coverage
   gaps block the build, matching the project's existing validation ethos.

## Architecture — three layers

### L1 — UI chrome, translated everywhere, inlined

- All interface strings in `tools/templates/lab.html`, `container.html`, and
  `gamification/index.html` move behind keys: a `t(key, vars)` helper reading
  from an inlined `I18N` object (all locales), plus `data-i18n="key"`
  attributes for static markup.
- Dictionaries live in `data/i18n/ui/<lang>.json` — flat key→string maps.
  `en.json` is the source of truth; every other file must cover exactly its
  key set (build-blocking validator in `build_lab.py`).
- `build_lab.py` stamps the full locale bundle into each generated page as a
  `<script type="application/json" id="i18n">` block.
- Strings with interpolation use `{name}` placeholders (`"{n} cards"`).
  Plural-sensitive strings get `_one`/`_other` key variants; the `t()` helper
  picks by count. No i18n library — the helper is ~20 lines.
- Game titles and blurbs (105 games, defined in `data/labs/*.json`) are UI
  chrome for this purpose: translated in `data/i18n/labs/<lang>.json` keyed
  by `<labid>.<gameid>.title` / `.blurb`, inlined the same way.

### L2 — Card content, lazy per-language overlays

- Translatable card fields: `label`, `sub`, `why`, `hint`, `note`, `snippet`,
  zone `def`, brief/scenario/rubric prose, ladder/pair prose. NOT translated:
  `answer`, `options`, zone `key`/`name`, `citation` identifiers, service
  names, statute names.
- Source translations live in `data/i18n/decks/<deck-path>.<lang>.json`,
  mirroring `data/decks/` structure: `{ "<item-id>": {"why": "...", ...} }`.
- `build_lab.py` compiles them into per-lab overlay bundles
  `gamification/i18n/<labid>.<lang>.json` containing only what that lab uses.
- Runtime: picking a non-English language fetches the overlay once, caches it
  in memory, and merges fields over the inlined English at render time
  (English remains the fallback per-field). Fetch failure → English cards,
  translated UI, no error surfaced beyond a subtle one-line note.
- Coverage validator: every item id in a source deck must appear in every
  language's overlay for the translated fields, or the build fails with the
  list of missing ids.

### L3 — AI handoff in the reader's language

- The existing Claude/ChatGPT/Perplexity reveal links append
  `Please respond in {language-name}.` when the active language ≠ en.

## Language selection & persistence

- The landing page's flag dropdown becomes the site-wide pattern, rendered in
  every page header (labs, containers, index). Flags: keep existing three
  SVGs; new languages get small inline-SVG flags or two-letter code chips in
  the same brutalist frame (decision: **code chips** — no 14 new flag assets,
  no flag-vs-language politics).
- First visit: match `navigator.language` (primary subtag, `zh-*`→`zh`,
  `pt-*`→`pt`) against supported list, else `en`. Stored in
  `localStorage["0pies.lang"]`; dropdown always overrides; egy/kli are never
  auto-detected.
- On switch: update `<html lang>`, swap all `data-i18n` nodes and re-render
  the active view (the lab engine already re-renders wholesale — `render()`
  is called after language change).
- egy/kli on the landing page migrate into the same dictionary mechanism
  (their existing `data-egy`/`data-kli` values become `egy.json`/`kli.json`
  entries) and keep their body-font-swap classes. Behavior identical.
- **Landing-page caveat:** `gamification/index.html` is hand-edited and not
  reproducible from its stale template (documented in README). Its i18n work
  is done directly on the live file; the stale template is left alone.

## Fonts & script support

- No new font downloads. Space Mono covers latin/latin-ext/vietnamese; all
  other scripts fall through the stack per-glyph to system fonts, which cover
  CJK/Arabic/Cyrillic/Devanagari on every modern OS. This matches the site's
  documented offline behavior ("offline you get system fonts").
- Font stacks gain explicit fallbacks:
  `"Space Mono", ui-monospace, SFMono-Regular, Menlo, "Noto Sans Mono", "Noto Sans", system-ui, sans-serif`.
- `egy` keeps Noto Sans Egyptian Hieroglyphs; `kli` keeps its current font
  class. Untouched.

## RTL (Arabic)

- `ar` sets `dir="rtl"` on `<html>`. Flexbox/grid layouts mirror
  automatically. The world-map containers get explicit `dir="ltr"`
  (geography doesn't mirror). Known asymmetric details (border-left snippets,
  box-shadow offsets) are accepted as-is for v1 unless verification shows
  breakage — the brutalist style tolerates mirrored shadows.

## Translation production (Haiku agents)

- A protected-terms glossary at `data/i18n/glossary.json`: service names,
  statute names, exam terms, and per-language conventions. Every translation
  agent receives it.
- UI dictionaries: one agent per language, translating `en.json` (+ labs
  file). Small, fast, reviewable diffs.
- Deck overlays: parallelizable one agent per (deck × language) or batched
  per language. Validator catches gaps; agents re-run on failures only.
- All translations are checked-in files — reviewable, correctable via PRs,
  no runtime API, no cost after authoring.

## Testing

1. **Build-time (blocking):** locale key coverage; overlay id coverage;
   placeholder integrity (`{n}` present in translation iff present in
   source); no English-only leaks in `data-i18n` nodes (template lint).
2. **verify_labs.mjs extension:** for each lab × each language — switch via
   dropdown, assert marked strings changed from English, assert overlay
   fetched and merged (spot-check one card's `why`), assert zero console
   errors. For `ar`: assert `dir=rtl` and take a screenshot; for `zh`:
   screenshot for tofu spot-check.
3. **file:// degradation test:** headless run with fetch blocked — UI
   translates, cards stay English, no errors.
4. **egy/kli regression:** landing page swaps still work, fonts still apply.

## Phasing (for the implementation plan)

1. **Infra + pilot:** i18n helper, dictionaries, dropdown, build changes,
   validators, `en` + `es` (volume) + `ar` (RTL) end-to-end. Landing-page
   migration of egy/kli onto the dictionary mechanism.
2. **Remaining 12 UI locales.**
3. **Deck overlays**, per language, parallel agents, validator-gated.
4. **Verification suite** extension and full-matrix run.

## Out of scope

- Translating citations' *content* (identifiers stay as-is everywhere).
- Localized URLs/pages per language (one page, runtime switch).
- The AIGP knowledge corpus prose beyond fields surfaced on cards.
- Translation memory tooling; the JSON files are the memory.
